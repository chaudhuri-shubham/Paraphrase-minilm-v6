🧾 Tab 1 — Summary of Changes (Bullet Format)

Title: Change in Error Classification for Data Extraction – Handling of Failed File Issues


---

🔹 Background

Earlier, all extraction issues such as unreadable, encrypted, or unsupported files were categorized under “Failed File Issue.”

This made it difficult to distinguish between genuine technical extraction failures and non-actionable cases (like password-protected or out-of-scope files).



---

🔹 What Has Changed

The logic has been updated to separate true failures from exceptions.

Two new exception categories have been introduced:

Password Protected – files intentionally locked or encrypted.

Out of Scope – files that fall outside the defined extraction scope (e.g., unsupported format, irrelevant type).


These exceptions are no longer counted as “Failed File Issues.”



---

🔹 Why the Change Was Needed

To ensure more accurate failure rate metrics.

To differentiate between system limitations and intentional file restrictions.

To reduce the number of false positives under the failure category.

To improve reporting transparency for stakeholders and reviewers.



---

🔹 Impact / Benefits

Provides clearer categorization of error types.

Helps the QA and Analytics teams focus only on true technical failures.

Failure rate now reflects real code or data issues, not external file constraints.

Enables better root cause analysis and tracking of issues over time.
